# Gatepost D2D app data (schema_version 1, route v3)

v3 (2026-10-23): every street is knocked in a single zigzag pass (`knock_both_sides`); repeat passes are `walk_no_knock`. `knock_one_side` is no longer produced. Step text is plain language ("Turn right onto ... Walk N feet to ... Knock both sides."); steps also carry `turn` (start/R/L/Rbear/Lbear/straight/around) and `destination`. v2 data is kept in `data/v2/`.

All coordinates are WGS84 `[lon, lat]` (GeoJSON order). Generated by `v2/d2d.py ... --geojson` (or `--geojson-only`) from the same
cached OSM data and plan/verify pipeline as the printable PDFs, so step text and geometry match the printable exactly.

## index.json
```
{ "schema_version": 1,
  "rules": { "phone", "permit", "badge", "no_soliciting", "hours", "mailboxes", "restroom", "contact", "full_text" },   // shared text
  "neighborhoods": [ { "name", "slug", "round", "file", "center":[lon,lat], "bbox":[w,s,e,n],
      "parking": {"name","address","url","coordinates":[lon,lat]}, "restroom", "sessions",
      "total_mi", "total_homes", "total_steps", "total_minutes" } ] }
```
Entries are keyed by (`slug`, `round`); re-running a build replaces its own entry and keeps the others.

## <slug>.geojson
A FeatureCollection with top-level `schema_version, name, slug, round, total_mi, total_homes, verification[]` and features
distinguished by `properties.kind`:

| kind | geometry | properties |
|---|---|---|
| `parking` | Point | `name, address, url` (Google Maps directions), `restroom` (nearest restroom/water/gas stop) |
| `session_path` | LineString | `session` (1..3), `color` (RED/BLUE/GOLD), `color_hex`, `line_dash` (PDF dash pattern, [] = solid), `mi, homes, minutes, steps, streets[], length_m` |
| `step` | LineString | `session, step` (1-based, matches PDF numbering), `text` (verified/fixed instruction, identical to PDF), `mode`, `knock_side`, `pass_no`, `mode_label`, `distance_ft` (exact; text rounds to 50 ft), `street`, `start, end` ([lon,lat]) |

- `session_path` is the full ordered closed walk from P back to P (the drawn route). Concatenating a session's `step` LineStrings in `step` order gives the same path; each step's first point equals the previous step's last point.
- `mode`: `knock_both_sides` | `knock_one_side` | `walk_no_knock`. For `knock_one_side`, `knock_side` is always `"right"` (relative to walking direction) and `pass_no` is 1 (first pass) or 2 (coming back, doing the other side). Otherwise both are null.
- Colors: 1 RED `#d62020`, 2 BLUE `#1f5fd6`, 3 GOLD `#c77800`. Minutes = 20 min/mi + 0.75 min/home, rounded to 15.

## Adding neighborhoods / round-2 routes
`cd v2 && python3 d2d.py --geojson-only --name ... --lat ... --lon ... --radius ... --park-name ... --park-lat ... --park-lon ... [--round 2] [--geojson-out ../app_data]`
writes `<slug>.geojson` and upserts index.json. For round 2 in the same neighborhood use a distinct `--name` (e.g. "Star Heights / Arlene Rd R2") so the file slug differs, plus `--round 2`.
Check with `python3 validate_geojson.py` (compares against the printable plan JSONs; run after `--print`).
